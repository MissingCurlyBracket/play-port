# Architecture — Frontend SPA (web)

**Date:** 2026-07-05
**Part:** `src/`
**Project Type:** web (React single-page application)

## Executive Summary

The frontend is a React 19 + TypeScript single-page app built with Vite and
served as static files from GitHub Pages under the base path `/play-port/`. It
uses TanStack Router (hash history, so deep links work on GitHub Pages) for
routing and TanStack React Query for server-state caching. UI is built with MUI
(a dark custom theme) wrapped in an atomic-design component library, with
Tailwind available for utility styling. The app is stateless server-side; user
preferences live in cookies.

## Architecture Pattern

**Component-based SPA with container/presentational separation and
dependency-injected services.**

- **Composition root:** `src/main.tsx` builds a `QueryClient` and one instance of
  each API client (`SearchApi`, `TitleApi`, `RegionApi`, `ProviderApi`,
  `TrendingApi`, `PopularApi`), then passes them into the router's `context`.
  This is the single dependency-injection seam.
- **Routes = containers:** each file route (`src/routes/`) pulls services from
  `Route.useRouteContext()`, prefetches data in a `loader`, runs `useQuery` /
  `useMutation`, and hands plain data + callbacks to a page.
- **Pages = presentational:** `MainPage` / `TitlePage` take data and functions as
  props and own only view-local UI state (search term, modal state, overview
  expand/clamp). They never import API clients directly, which keeps them easy to
  render in isolation and test.
- **Atomic-design UI:** `atoms/` (`Base*` MUI wrappers) → `molecules/` → `organisms/`
  → `templates/`.

## Routing

TanStack Router with **hash history** (`createHashHistory`) — required because
GitHub Pages can't do SPA path rewrites. `autoCodeSplitting` is on. Routes:

| Path | File | Responsibility |
|---|---|---|
| `/` | `routes/index.tsx` | Home: prefetch regions + trending; search mutation; render `MainPage` |
| `/title/$type/$id` | `routes/title/$type/$id.tsx` | Prefetch title details + providers (region/providers from cookies); render `TitlePage` |
| `/dev/bones` | `routes/dev/bones.tsx` | Dev-only surface for capturing boneyard skeleton shapes |
| (root) | `routes/__root.tsx` | Layout: floating back button on non-home routes, `<Outlet/>`, router devtools |

`src/routeTree.gen.ts` is generated by the router's Vite plugin — never edit it.

## Data / State Architecture

- **Server state:** TanStack React Query. Query keys in use: `['regions']`,
  `['trending']`, `['title', type, id]`, `['providers', type, id, region, providers]`;
  search uses a mutation keyed `['search']`. Route `loader`s call
  `queryClient.prefetchQuery` so components render with warm caches.
- **Client/UI state:** local `useState` in pages (search input with `use-debounce`
  at 400ms, preferences-dialog state, overview expand/clamp via `ResizeObserver`).
- **Persistent preferences:** region code and comma-joined provider IDs stored in
  cookies (`max-age=31536000`). Read via `src/utils/cookies.ts`; written in
  `MainPage.handleSaveSettings`. Preferences are forwarded to the backend as
  `region` / `providers` query params for provider and popular lookups.

## Deployment Architecture

Built with `npm run build` (`tsc -b && vite build`) and published to GitHub Pages
with `gh-pages` (`npm run deploy`), automated via GitHub Actions. `VITE_API_BASE_URL`
is injected at build time. See [deployment-guide.md](./deployment-guide.md).

## Testing Strategy

Vitest + jsdom with Chai assertions and `sinon` for stubs. `globals: true`.
Coverage is currently minimal (`src/api/PopularApi.test.ts`); the DI + interface
design makes API clients and presentational pages the natural test targets.

## Notable Constraints & Gotchas

- **Hash history is intentional** — do not switch to browser history without a
  Pages rewrite strategy, or deep links will 404.
- **`base: '/play-port/'`** must match the GitHub Pages project path; the MSW
  worker is served from `/play-port/mockServiceWorker.js`.
- **Single manual chunk** (`manualChunks: () => 'main'`) — the build intentionally
  emits one JS chunk.
