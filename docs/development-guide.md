# Development Guide

**Date:** 2026-07-05
**Scope:** Both parts (single npm package: SPA in `src/`, Lambda API in `functions/`).

## Prerequisites

- **Node.js 24** and **npm** (CI uses Node 24; the Lambda runtime is `nodejs24.x`).
- For the **real backend**: a TMDB v3 read access token. An OMDb key is optional
  (enables IMDb rating/genre/director/cast).
- No database, Docker, or other services are required.

## Install

```bash
npm install
```

## Environment variables

| Variable | Scope | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | frontend (`.env`, build-time) | Base URL the SPA's API clients call |
| `TMDB_READ_ACCESS_TOKEN` | backend (runtime) | TMDB v3 bearer token |
| `OMDB_API_KEY` | backend (runtime, optional) | OMDb key for IMDb enrichment |

`.env` and `.env.*` are gitignored. For the SPA, create `.env` with
`VITE_API_BASE_URL=...` (or rely on MSW in dev — see below). For the backend,
export `TMDB_READ_ACCESS_TOKEN` (and optionally `OMDB_API_KEY`) in your shell or a
local env file before running `serverless offline`.

## Running locally

### Frontend SPA (with mocked backend) — the common case

```bash
npm run dev
```

Vite serves the SPA. Because `import.meta.env.DEV` is true, MSW starts a service
worker and serves fixtures from `src/mocks/handler.ts` — **you need no backend and
no TMDB token** to develop the UI. Search/provider mocks include a 2s delay so
skeleton loaders are visible.

### Backend API (real TMDB) locally

```bash
export TMDB_READ_ACCESS_TOKEN=...   # and optionally OMDB_API_KEY
npx serverless offline
```

Runs the Lambda handlers behind a local HTTP API. To point the SPA at it instead
of MSW, set `VITE_API_BASE_URL` to the offline URL — note MSW still intercepts in
dev, so to test against the real backend either run a production-style build or
temporarily disable the MSW startup in `src/main.tsx`.

## Testing

Vitest with Chai assertions in a jsdom environment (`globals: true`), `sinon` for
stubs. Current coverage is minimal (`src/api/PopularApi.test.ts`). Good test
targets given the architecture: the `src/api/*` clients (stub `fetch`),
presentational pages (`MainPage`/`TitlePage` via props), and backend handlers
(pure `event → response`, stub `fetch`).

## Code style

- **Prettier:** single quotes, semicolons, trailing commas, 2-space indent, 80-char width.
- **ESLint:** flat config (`eslint.config.js`) with TypeScript, React, React Hooks,
  and Prettier plugins. Run `npm run lint`.
- Match the surrounding atomic-design + container/presentational conventions.

## Working conventions & gotchas

- **Do not edit `src/routeTree.gen.ts`** — regenerated by the TanStack Router Vite plugin.
- **New network call?** Add/extend a `src/api/*` client (don't inline `fetch`), and
  if it's a new client, instantiate it in `main.tsx` and add it to the router
  context type in `__root.tsx`.
- **New backend endpoint?** Export a handler in `functions/handler.ts`, add the
  function + `httpApi` event in `serverless.yml`, and add a matching MSW handler in
  `src/mocks/handler.ts`. Update `docs/api-contracts-backend.md`.
- **Skeletons:** capture bone shapes from `/dev/bones` via `npm run capture-bones`
  (which also runs `scripts/remap-bones.mjs`), and register shapes in `src/bones/`.
- **Hash routing + `base: '/play-port/'`** are load-bearing for GitHub Pages — keep them.
